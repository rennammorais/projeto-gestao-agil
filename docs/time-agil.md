# Papéis do time
* **Luma (Product Owner e Developer):** Responsável por maximizar o valor do produto e gerenciar o Backlog. É quem define o escopo, garante que as histórias de usuário façam sentido para nômades digitais e aprova as entregas. Como Developer, atua na codificação.
* **Rennan Morais de Araujo (Scrum Master e Developer):** Responsável por garantir que o Scrum/Kanban seja seguido, remover impedimentos técnicos (ex: bugs no ambiente Windows/VS Code) e gerenciar a infraestrutura. Como Developer, codifica o sistema distribuído e banco de dados.

# Definition of Ready
Para uma issue entrar na coluna DOING, ela deve, verificavelmente:
1. Ter uma História de Usuário escrita e clara.
2. Possuir Critérios de Aceitação descritos em checklist.
3. Ter a prioridade MoSCoW classificada.
4. Ter o escopo técnico discutido pela dupla.

# Definition of Done
Para uma issue ir para a coluna DONE, as seguintes condições (as mesmas do PR) devem ser cumpridas:
1. Código compila sem erros no VS Code (Java/C).
2. Funcionalidade atende a 100% dos critérios de aceitação da issue.
3. Código validado por Code Review do outro membro da dupla via Pull Request.

# Matriz de stakeholders
* **Alto Poder / Alto Interesse (Gerenciar de perto):** Professores e nômades digitais (usuários finais). Estratégia: Entregas pontuais e validação contínua de infraestrutura.
* **Alto Poder / Baixo Interesse (Manter satisfeitos):** Provedores de Gateways de Pagamento. Estratégia: Cumprir rigorosamente a documentação da API.
* **Baixo Poder / Alto Interesse (Manter informados):** Locadores e proprietários de imóveis. Estratégia: Fornecer manuais de como cadastrar imóveis e requisitos de internet.
* **Baixo Poder / Baixo Interesse (Monitorar):** Redes de hotéis tradicionais. Estratégia: Observar os preços de mercado para manter a plataforma competitiva.

# Plano de comunicação
* **Sincronização do Time:** Diariamente via WhatsApp para repassar tarefas e impedimentos.
* **Acompanhamento de Tarefas:** Em tempo real, através do quadro Kanban no GitHub Projects.
* **Reporte de Status:** Para o professor e avaliadores, via AVA, nas datas dos Milestones.

# Quadro e limite de WIP
O limite de WIP da coluna DOING é **2**.
**Justificativa:** Como o time possui apenas dois desenvolvedores (Rennan e Luma), o limite garante que cada um foque em apenas 1 (uma) tarefa por vez. Isso evita a troca constante de contexto (context switching) e garante que as tarefas sejam finalizadas antes de novas serem iniciadas.
